# 冷知识星球 - 推荐算法设计

> 版本: v1.1 | 更新日期: 2026-05-14

---

## 一、推荐目标与原则

### 1.1 推荐目标

| 目标 | 说明 | 核心指标 |
|------|------|----------|
| 用户留存 | 让用户每天愿意打开 App | 7 日留存率 |
| 内容消费 | 让用户多浏览知识卡片 | 日均浏览卡片数 |
| 兴趣沉淀 | 让用户找到感兴趣的内容 | 收藏率 |
| 内容发现 | 让优质内容被更多人看到 | 内容覆盖率 |

### 1.2 设计原则

**原则 1: 碎片化友好**
- 用户每次打开 App 只看 3-10 张卡片
- 推荐结果必须"开箱即用"，无需用户思考
- 第一张卡片就要吸引用户

**原则 2: 兴趣探索与利用的平衡**
- 70% 推荐用户已知兴趣类目（利用）
- 30% 推荐用户未接触类目（探索）
- 避免"信息茧房"

**原则 3: 内容新鲜感**
- 同一用户不重复推荐已看过的卡片
- 新发布内容有优先曝光机会
- 定期刷新推荐池

**原则 4: 冷启动友好**
- 新用户首次打开就有优质内容推荐
- 不依赖用户历史行为
- 快速收集用户兴趣信号

## 二、推荐策略设计

### 2.1 策略总览

```
┌─────────────────────────────────────────────────────────────────┐
│                         推荐策略矩阵                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│                    用户状态                                      │
│         ┌──────────────┬──────────────┐                         │
│         │   新用户      │   老用户      │                         │
│    ┌────┼──────────────┼──────────────┤                         │
│    │无行为│  热门推荐    │  热门推荐     │                         │
│ 行 ├────┼──────────────┼──────────────┤                         │
│ 为 │有行为│  兴趣推荐    │  混合推荐     │                         │
│    └────┴──────────────┴──────────────┘                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**名词解释**:

| 概念 | 定义 | 示例 |
|------|------|------|
| **新用户** | 注册 ≤ 7 天，或浏览卡片数 < 20 | 刚下载 App 的用户 |
| **老用户** | 注册 > 7 天，且浏览卡片数 ≥ 20 | 使用超过一周的活跃用户 |
| **无行为** | 没有产生有效兴趣信号的行为 | 仅快速滑过卡片（浏览 < 3秒）、未收藏、未点击 AI 解读 |
| **有行为** | 产生了有效兴趣信号的行为 | 认真浏览卡片（浏览 ≥ 3秒）、收藏、点击 AI 延伸解读 |

**策略矩阵举例**:

| 场景 | 用户画像 | 推荐策略 | 推荐内容示例 |
|------|----------|----------|-------------|
| 新用户 + 无行为 | 刚注册，快速滑过几张卡片 | 热门推荐 | 全站浏览量 TOP 10 的知识卡片 |
| 新用户 + 有行为 | 刚注册，收藏了 2 张科学类卡片 | 兴趣推荐 | 科学类热门内容 + 其他类目探索内容 |
| 老用户 + 无行为 | 活跃用户，今天只是随便看看 | 热门推荐 | 今日热门 + 新发布内容 |
| 老用户 + 有行为 | 活跃用户，经常浏览历史类内容 | 混合推荐 | 70% 历史类 + 20% 相关类目 + 10% 探索类目 |

### 2.2 策略一：热门推荐

**适用场景**: 新用户、未登录用户、用户主动刷新

**设计思路**:
- 热门 = 大众认可 = 容错率高
- 新用户第一次看到的内容质量有保障
- 避免推荐冷门内容导致用户流失

**热度公式**:
```
热度分 = 浏览量 + 收藏量 × 5 + AI延伸解读量 × 3 + 运营卡片权重 × 10
```

**权重设计理由**:
- 浏览量：基础热度指标
- 收藏量 × 5：收藏是强正向信号，用户认为值得保存
- AI 延伸解读量 × 3：用户主动点击 AI 延伸解读，说明对内容感兴趣
- 运营卡片权重 × 10：运营人员手动调整的权重（-2 到 2），可加权推广或降权惩罚

**时间衰减**:
- 7 天内发布的内容热度分 × 1.5
- 30 天内发布的内容热度分 × 1.0
- 30 天前发布的内容热度分 × 0.8

### 2.3 策略二：兴趣推荐

**适用场景**: 已登录且有行为历史的用户

**设计思路**:
- 基于用户历史行为构建兴趣画像
- 推荐与用户兴趣匹配的内容
- 兴趣会随时间变化，需要动态更新

**兴趣画像构建**:

```
用户兴趣 = Σ (行为权重 × 内容特征)
```

**内容特征说明**:

内容特征是知识卡片的属性标签，用于描述"这条内容是什么"。在本项目中，内容特征主要指：

| 特征维度 | 存储位置 | 示例 |
|---------|----------|------|
| 类目（一级特征） | `t_category` | 日常生活、自然科学、科学原理、数学趣闻、历史故事 |
| 标签（二级特征） | `t_knowledge.tags` | 动物、宇宙、冷门、有趣、量子、恐龙 |
| 资源类型 | `t_knowledge.type` | 图文、视频、音频 |

**公式含义示例**:

假设用户对以下内容有行为：

| 内容 | 类目 | 标签 | 行为 | 行为权重 |
|------|------|------|------|---------|
| 卡片A | 科学 | 量子、物理 | 收藏 | +5 |
| 卡片B | 科学 | 天文、黑洞 | 浏览30秒 | +3 |
| 卡片C | 历史 | 古代、战争 | 浏览10秒 | +2 |

则用户兴趣向量 = 5×(科学+量子+物理) + 3×(科学+天文+黑洞) + 2×(历史+古代+战争)

**一级兴趣（类目）**: 科学=8, 历史=2
**二级兴趣（标签）**: 量子=5, 物理=5, 天文=3, 黑洞=3, 古代=2, 战争=2

结论：该用户对"科学"类目兴趣最高，对"量子"和"物理"标签最感兴趣，应优先推荐科学类量子/物理相关内容。

**行为信号定义**:

| 行为 | 权重 | 说明 |
|------|------|------|
| 浏览（时长 < 3秒） | +0 | 快速滑过，无兴趣信号 |
| 浏览（3-10秒） | +1 | 正常浏览，基础兴趣 |
| 浏览（10-30秒） | +2 | 认真阅读，中等兴趣 |
| 浏览（> 30秒） | +3 | 深度阅读，强兴趣 |
| 收藏 | +5 | 强兴趣信号 |
| 点击 AI 延伸解读 | +2 | 主动探索，中等兴趣 |

**兴趣衰减机制**:
- 每天衰减 5%（乘以 0.95）
- 30 天无互动的兴趣分衰减至原来的 21%
- 避免过时兴趣影响推荐

### 2.4 策略三：混合推荐

**适用场景**: 老用户（有丰富行为历史）

**设计思路**:
- 单一策略都有局限性
- 多策略融合，取长补短
- 动态调整各策略权重

**融合公式**:
```
最终推荐分 = 兴趣分 × 0.4 + 热度分 × 0.3 + 新鲜度分 × 0.2 + 运营权重分 × 0.1
```

**各分项说明**:

| 分项 | 计算方式 | 作用 |
|------|----------|------|
| 兴趣分 | 用户对该类目/标签的兴趣分数 | 个性化匹配 |
| 热度分 | 全局热度排名归一化 | 保证内容质量 |
| 新鲜度分 | 发布时间越近分数越高 | 新内容曝光 |
| 运营权重分 | 卡片权重 × 类目权重 | 运营干预 |

**权重可调整**:
- 运营可根据业务目标调整权重
- A/B 测试找到最优权重组合
- 不同用户群组可使用不同权重

## 三、用户画像设计

### 3.1 两级兴趣体系

```
用户兴趣画像
├── 一级兴趣：类目维度
│   ├── 日常生活
│   ├── 自然科学
│   ├── 科学原理
│   ├── 数学趣闻
│   ├── 历史故事
│   ├── 动物世界
│   ├── 植物王国
│   ├── 人体奥秘
│   ├── 科技前沿
│   └── 文化艺术
│
└── 二级兴趣：标签维度
    ├── 具体标签（如"黑洞"、"恐龙"、"量子"）
    ├── 每个标签独立计分
    └── 标签兴趣可跨类目
```

### 3.2 兴趣分数计算

**一级兴趣（类目）**:
```
类目兴趣分 = Σ (该类目下所有卡片的行为权重) × 运营类目权重
```

**二级兴趣（标签）**:
```
标签兴趣分 = Σ (含该标签的所有卡片的行为权重)
```

**兴趣优先级**:
- 一级兴趣决定大方向（推荐哪个类目）
- 二级兴趣决定精准度（推荐类目下的哪些卡片）
- 二级兴趣可跨类目（如用户喜欢"黑洞"，可能也喜欢物理学相关内容）

### 3.3 兴趣信号采集

**主动信号**:
- 首次登录选择的兴趣类目
- 收藏行为

**被动信号**:
- 浏览行为（看了什么类目/标签）
- 浏览时长（推断兴趣强度）
- AI 延伸解读点击（主动探索信号）

### 3.4 三端参与流程

#### 客户端（采集层）

**职责**: 采集用户行为原始数据，上报至服务端

**信号采集点**:

| 用户操作 | 采集内容 | 上报时机 | 体现位置 | 去重规则 |
|---------|----------|----------|----------|----------|
| 首次登录 | 选择的兴趣类目列表 | 选择完成时 | 注册引导页 | 一次性 |
| 浏览卡片 | 卡片ID、类目、标签、开始时间 | 卡片离开时（滑走/退出） | 首页卡片流、卡片详情页 | 同一用户同一卡片仅计1次 |
| 浏览时长 | 停留秒数 | 卡片离开时 | 首页卡片流、卡片详情页 | 同一用户同一卡片仅计1次 |
| 收藏/取消收藏 | 卡片ID、操作类型 | 操作发生时 | 卡片左下角收藏按钮、卡片详情收藏按钮 | 状态切换，不去重 |
| 点击 AI 延伸解读 | 卡片ID | 点击时 | 卡片底部 AI 解读入口、卡片详情AI延伸解读 | 同一用户同一卡片仅计1次 |
| 上划加载更多 | 加载时间戳 | 加载触发时 | 首页卡片流底部 | 不去重 |
| 类目筛选 | 筛选的类目ID | 筛选时 | 首页顶部类目标签栏 | 不去重 |
| 卡片筛选 | 卡片搜索项 | 搜索时 | 发现页顶部搜索 | 不去重 |

**数据格式**:
```
行为上报 = {
  用户ID,
  卡片ID,
  行为类型（浏览/收藏/AI解读）,
  浏览时长（秒）,
  时间戳
}
```

#### 服务端（计算层）

**职责**: 接收行为数据，更新用户兴趣画像，执行推荐算法

**处理流程**:

```
客户端上报行为
      │
      ▼
┌─────────────────┐
│  行为数据入库    │  → t_behavior_log（行为日志表）
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  计算行为权重    │  → 根据行为类型和浏览时长计算权重分
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  更新兴趣画像    │  → t_user_interest（用户兴趣表）
│  - 一级兴趣(类目)│     累加类目兴趣分
│  - 二级兴趣(标签)│     累加标签兴趣分
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  兴趣分数衰减    │  → 定时任务，每天衰减 5%
└─────────────────┘
```

**存储体现**:

| 数据 | 存储位置 | 说明 |
|------|----------|------|
| 用户行为日志 | `t_behavior_log` | 原始行为记录，用于离线分析 |
| 用户一级兴趣 | `t_user_interest`（type=category） | 类目维度的兴趣分数 |
| 用户二级兴趣 | `t_user_interest`（type=tag） | 标签维度的兴趣分数 |
| 内容热度统计 | `t_knowledge`（view_count, favorite_count） | 卡片维度的热度指标 |

#### 后台运营（干预层）

**职责**: 通过权重配置影响推荐结果，监控推荐效果

**干预方式**:

| 干预手段 | 操作位置 | 影响范围 | 说明 |
|---------|----------|----------|------|
| 卡片权重配置 | 知识管理 → 编辑卡片 | 单张卡片 | 设置 -2 到 2 权重，加权推广或降权惩罚 |
| 类目权重配置 | 类目管理 → 编辑类目 | 整个类目 | 设置 -2 到 2 权重，加权推广或降权惩罚 |
| 内容上下架 | 知识管理 → 上架/下架 | 单张卡片 | 下架内容不再进入推荐池 |
| 推荐效果监控 | Dashboard → 推荐指标 | 全局 | 查看点击率、收藏率、类目分布等指标 |
| 兴趣分布查看 | 用户管理 → 用户画像 | 单个用户 | 查看用户兴趣标签和分数分布 |

**运营看板体现**:

```
推荐效果监控
├── 实时数据
│   ├── 今日推荐次数
│   ├── 点击率 (CTR)
│   ├── 收藏率
│   └── AI延伸解读率
├── 类目分析
│   ├── 各类目推荐占比
│   ├── 各类目点击率对比
│   └── 类目热度趋势
├── 用户分析
│   ├── 兴趣分布（Top 类目/标签）
│   ├── 活跃度分层
│   └── 新老用户占比
└── 内容分析
    ├── 热门卡片 Top 20
    ├── 新内容曝光效果
    └── 低质内容预警
```

## 四、内容画像设计

### 4.1 内容特征

```
内容画像
├── 基础属性
│   ├── 类目归属（一级）
│   ├── 标签列表（二级）
│   └── 资源类型（图文/视频/音频）
├── 质量指标
│   ├── 收藏率 = 收藏数 / 浏览数
│   └── AI延伸解读率 = AI点击数 / 浏览数
├── 热度指标
│   ├── 浏览量
│   ├── 收藏量
│   └── AI延伸解读量
└── 运营指标
    ├── 卡片权重（-2 到 2）
    └── 类目权重（-2 到 2）
```

### 4.2 运营权重机制

**卡片权重（-2 到 2）**:
- -2：强降权，低质/敏感内容
- -1：轻度降权，质量一般内容
- 0：默认权重，无特殊处理
- 1：中等加权，适度增加曝光
- 2：强加权，优先推荐

**类目权重（-2 到 2）**:
- -2：强降权，过季/过剩类目
- -1：轻度降权，暂时减少曝光
- 0：默认权重，无特殊处理
- 1：中等加权，该类目内容适度增加曝光
- 2：强加权，该类目内容优先推荐

**权重应用场景**:
- 节日/活动期间加权相关类目
- 新上线内容加权推广
- 优质内容加权曝光
- 低质内容降权处理

### 4.3 内容质量评估

**质量分 = 收藏率 × 100 + AI延伸解读率 × 50**

**质量等级**:

| 等级 | 质量分范围 | 说明 | 推荐策略 |
|------|-----------|------|----------|
| 优质 | ≥ 15 | 收藏率 ≥ 10% 或 AI解读率 ≥ 20% | 优先推荐 |
| 普通 | 5 - 15 | 有一定互动但不突出 | 正常推荐 |
| 低质 | < 5 | 收藏率 < 3% 且 AI解读率 < 5% | 降权或下架 |

**质量分计算示例**:

| 内容 | 浏览量 | 收藏 | AI解读 | 收藏率 | AI解读率 | 质量分 | 等级 |
|------|--------|------|--------|--------|----------|--------|------|
| 卡片A | 1000 | 150 | 200 | 15% | 20% | 15 + 10 = 25 | 优质 |
| 卡片B | 500 | 30 | 25 | 6% | 5% | 6 + 2.5 = 8.5 | 普通 |
| 卡片C | 200 | 3 | 5 | 1.5% | 2.5% | 1.5 + 1.25 = 2.75 | 低质 |

**说明**:
- 质量分仅反映内容本身的用户反馈质量，与运营权重独立
- 运营权重通过推荐公式中的"运营权重分"单独影响推荐排序
- 新内容（浏览量 < 100）不计算质量分，进入新内容池单独评估

## 五、推荐流程设计

### 5.1 整体流程

```
用户请求推荐
      │
      ▼
┌─────────────────┐
│  判断用户状态    │
└────────┬────────┘
         │
    ┌────┴────────────────┐
    ▼                     ▼
  新用户/无行为          有行为历史
    │                     │
    ▼                     ▼
┌────────────┐     ┌────────────┐
│  热门推荐   │     │  混合推荐   │
└────┬───────┘     └────┬───────┘
     │                  │
     ▼                  ▼
┌────────────────────────────────┐
│         结果后处理              │
│  - 去重（已看过的内容）          │
│  - 多样性控制（类目分布）        │
│  - 运营干预（权重加成）          │
└────────────────────────┬───────┘
                         │
                         ▼
                  返回推荐结果
```

### 5.2 候选集生成

**Step 1: 基础过滤**
- 仅推荐上架状态的内容
- 排除用户已收藏的内容
- 排除用户已浏览过的内容（除非主动刷新）

**Step 2: 类目召回**
- 用户一级兴趣 Top 5 类目 → 召回该类目下内容
- 全局热门类目 → 召回热门内容
- 新发布内容 → 召回新内容

**Step 3: 标签召回**
- 用户二级兴趣 Top 10 标签 → 召回含该标签内容
- 跨类目召回相关内容

**Step 4: 候选集合并**
- 去重
- 候选集大小：200-500 条

### 5.3 排序策略

**粗排**（候选集 → 精选集）:
- 基于简单规则快速筛选
- 保留 50-100 条进入精排

**精排**（精选集 → 推荐列表）:
- 使用融合公式计算最终得分
- 考虑多样性约束
- 应用运营权重
- 生成最终推荐列表

### 5.4 多样性控制

**类目多样性**:
- 连续 3 张卡片不能来自同一类目
- 每 10 张卡片至少覆盖 3 个类目

**内容类型多样性**:
- 图文、视频、音频交替出现
- 避免连续推荐同类型内容

**热度多样性**:
- 热门内容占比 60%
- 中等内容占比 30%
- 冷门内容占比 10%

### 7.1 核心指标体系

```
推荐效果指标
├── 用户体验指标

│   ├── 停留时长 = 平均每张卡片浏览时间

│   ├── 日活跃用户数 (DAU)
│   ├── 7 日留存率
│   ├── 日均浏览卡片数
│   └── 用户生命周期价值 (LTV)
├── 内容生态指标
│   ├── 内容覆盖率 = 被推荐过的卡片占比
│   ├── 类目均衡度 = 各类目推荐占比的标准差
│   └── 新内容曝光率 = 新内容被推荐的比例
└── 算法效果指标
    ├── 兴趣匹配度 = 兴趣类目内容占比
    ├── 推荐多样性 = 推荐类目分布熵
    └── 推荐新颖度 = 首次推荐内容占比
```

### 7.2 指标目标值

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 点击率 (CTR) | > 15% | 推荐内容吸引力 |
| 收藏率 | > 10% | 内容价值认可 |
| 日均浏览量 | > 10 张 | 用户活跃度 |
| 7 日留存率 | > 40% | 用户粘性 |
| 内容覆盖率 | > 80% | 内容分发均衡 |
| 兴趣匹配度 | > 60% | 个性化程度 |
| AI延伸解读率 | > 20% | 内容深度吸引力 |

## 八、运营干预机制

### 8.1 权重配置

**卡片权重（-2 到 2）**:

| 权重值 | 说明 | 使用场景 |
|--------|------|----------|
| -2 | 强降权 | 低质内容、敏感内容、待下架内容 |
| -1 | 轻度降权 | 质量一般、内容过时 |
| 0 | 默认 | 正常内容 |
| 1 | 中等加权 | 优质内容、活动内容 |
| 2 | 强加权 | 重点推广、节日主题 |

**类目权重（-2 到 2）**:

| 权重值 | 说明 | 使用场景 |
|--------|------|----------|
| -2 | 强降权 | 过季类目、内容过剩类目 |
| -1 | 轻度降权 | 暂时减少曝光的类目 |
| 0 | 默认 | 正常类目 |
| 1 | 中等加权 | 活跃类目、季节性类目 |
| 2 | 强加权 | 重点推广类目 |

### 8.2 系统配置

通过系统配置表（`t_system_config`，group=recommend）可动态调整推荐算法参数，无需修改代码。

**配置项列表**:

| 配置键 | 默认值 | 说明 | 影响范围 |
|--------|--------|------|----------|
| `recommend_content_weight` | 0.4 | 内容相似度权重 | 融合公式 - 兴趣匹配 |
| `recommend_hot_weight` | 0.3 | 热度权重 | 融合公式 - 热门内容 |
| `recommend_new_weight` | 0.2 | 新卡片权重 | 融合公式 - 新内容曝光 |
| `recommend_random_weight` | 0.1 | 随机权重 | 融合公式 - 探索与多样性 |
| `recommend_dedup_days` | 7 | 去重天数 | 已浏览卡片不再推荐的天数 |

**与融合公式的对应关系**:

```
最终推荐分 = 兴趣分 × recommend_content_weight
           + 热度分 × recommend_hot_weight
           + 新鲜度分 × recommend_new_weight
           + 随机分 × recommend_random_weight
           + 运营权重分
```

**配置调整建议**:

| 业务目标 | 调整策略 | 配置变更示例 |
|----------|----------|-------------|
| 提升个性化 | 增加兴趣权重 | content_weight: 0.4 → 0.6 |
| 推广新内容 | 增加新卡片权重 | new_weight: 0.2 → 0.4 |
| 增加探索性 | 增加随机权重 | random_weight: 0.1 → 0.3 |
| 强化热门 | 增加热度权重 | hot_weight: 0.3 → 0.5 |
| 延长去重 | 增加去重天数 | dedup_days: 7 → 14 |

**配置生效机制**:
- 配置变更实时生效（服务重启或缓存刷新）
- 建议配合 A/B 测试验证效果
- 记录配置变更日志，便于回溯

| 浏览时长上报 | 记录每张卡片的浏览时长并上报 |
| AI延伸解读 | 展示 AI 延伸解读入口，记录点击行为 |
| 收藏行为 | 上报收藏/取消收藏行为 |
| 交互体验 | 加载更多、下拉刷新、类目筛选 |
| 本地缓存 | 缓存推荐结果，提升加载速度 |

## 十、后续优化方向

### 10.1 短期优化（1-2 周）

**目标**: 完善基础推荐能力

- 完善浏览时长采集机制
- 实现兴趣衰减机制
- 实现推荐结果缓存
- 优化冷启动策略
- 接入客户端 API

### 10.2 中期优化（1-2 月）

**目标**: 提升推荐精准度

**基于内容的推荐**:
- 为内容构建特征向量（类目 + 标签 + 关键词）
- 计算用户画像与内容特征的相似度
- 推荐与用户历史喜好相似的内容

**协同过滤**:
- 基于用户行为构建用户-物品矩阵
- 找到相似用户群体
- 推荐相似用户喜欢的内容

**标签兴趣挖掘**:
- 分析用户浏览内容的标签分布
- 识别用户的二级兴趣标签
- 跨类目推荐相关内容

### 10.3 长期优化（3-6 月）

**目标**: 构建智能化推荐系统

**深度学习模型**:
- 使用深度学习模型预测用户点击概率
- 自动学习用户特征和内容特征的交互
- 持续优化模型效果

**实时推荐**:
- 实时收集用户行为
- 实时更新用户画像
- 实时调整推荐结果

**多目标优化**:
- 同时优化点击率、停留时长、收藏率
- 平衡短期指标和长期用户价值
- 实现帕累托最优

**推荐解释**:
- "因为你喜欢 [类目] 类内容"
- "基于你对 [标签] 的兴趣"
- "本周热门 TOP 10"
- 增强用户对推荐的信任感
