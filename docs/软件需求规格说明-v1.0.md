## 第一章：文档概述

### 1.1 文档目的

本文档为"冷知识星球"微信小程序的软件需求规格说明书（Product Requirements Document），旨在全面、清晰地描述产品的功能需求、非功能需求、数据结构及接口规范。

**目标读者：**

| 角色 | 阅读重点 |
|------|---------|
| 产品经理 | 全文，重点关注功能需求与业务规则 |
| UI/UX 设计师 | 第三、四章，重点关注页面结构与界面要求 |
| 前端开发 | 第三、四、七章，重点关注交互流程与接口规范 |
| 后端开发 | 第四、六、七章，重点关注业务规则、数据字典与接口设计 |
| 测试工程师 | 第四、五、七章，重点关注业务规则、性能要求与接口测试用例 |

### 1.2 产品概述

**冷知识星球**是一款面向碎片化学习场景的微信小程序，以图文卡片的形式向用户推送涵盖生活、大自然、科学、数学、历史等多个类目的小知识。用户可通过上下滑动浏览知识卡片，利用每天的零散时间轻松获取有趣的知识。产品同时集成 AI 能力，提供知识延伸解读和图片识别功能，帮助用户更深入地探索感兴趣的知识领域。

**产品定位：** 轻量级知识科普类微信小程序

**核心价值：**
- 碎片时间高效利用，每日进步一点点
- 丰富的知识类目，满足多元化兴趣
- AI 赋能，深度探索感兴趣的知识
- 每日打卡机制，培养持续学习习惯

### 1.3 品牌理念

> **探索未知，每日进步一点点**

冷知识星球相信，知识的积累源于每一天的好奇与探索。我们致力于将浩瀚的知识海洋浓缩为一张张精美的卡片，让用户在等车、排队、休息的碎片时间里，轻松获取一个有趣的知识点。每一次滑动都是一次小小的发现，每一天的坚持都是一次成长。

### 1.4 术语定义

| 术语 | 定义 |
|------|------|
| 知识卡片 | 小程序中最基本的内容单元，包含知识标题、文字描述、配图、类目标签等信息 |
| 类目 | 知识卡片的分类标签，如"生活常识"、"科学原理"等，共10个类目 |
| 收藏 | 用户将感兴趣的知识卡片保存到个人收藏夹的功能 |
| 纠错 | 用户对知识卡片内容提出修正意见的功能，包括内容错误、分类错误等 |
| 打卡 | 用户每日浏览一定数量的知识卡片后，记录当日学习行为的功能 |
| AI 延伸解读 | 基于当前知识卡片，由 AI 生成 2-3 条延伸相关知识或趣味解读的功能 |
| AI 图片识别 | 用户上传图片，由 AI 识别图片内容并生成相关知识卡片的功能 |
| 访客 | 未登录的用户，可浏览知识卡片但无法使用收藏、纠错、打卡等个性化功能 |
| 普通用户 | 已通过微信授权登录的用户，可使用全部功能 |
| 连续打卡 | 用户连续多日完成打卡的记录，中断后重新计数 |
| 里程碑 | 连续打卡达到特定天数（7天/30天/100天）时的成就标记 |

## 第二章：用户角色与场景

### 2.1 用户角色

#### 2.1.1 角色总览

| 角色 | 描述 | 核心诉求 | 使用频率 |
|------|------|---------|---------|
| 访客 | 未进行微信授权登录的用户 | 快速浏览知识卡片，了解产品功能 | 偶尔（首次使用时） |
| 普通用户 | 已通过微信授权登录的用户 | 每日获取有趣知识、收藏喜欢的卡片、坚持打卡 | 每日 1-5 次 |

#### 2.1.2 访客

- **描述：** 首次打开小程序或未进行微信授权的用户，处于"浏览模式"。
- **核心诉求：** 快速体验产品，了解知识卡片的内容质量和交互方式。
- **权限范围：**
  - 可浏览知识卡片（上下滑动切换）
  - 可按类目筛选卡片
  - 不可收藏、纠错、打卡、使用 AI 功能
  - 触发需要登录的功能时，弹出登录引导弹窗

#### 2.1.3 普通用户

- **描述：** 已完成微信授权登录的用户，拥有产品的完整使用权限。
- **核心诉求：**
  - 每日获取有趣的小知识，充实碎片时间
  - 收藏有价值的知识卡片，方便回顾
  - 通过打卡机制坚持每日学习
  - 利用 AI 功能深度探索感兴趣的知识
- **权限范围：** 可使用全部功能，包括收藏、纠错、打卡、AI 延伸解读、AI 图片识别等。

### 2.2 用户场景

#### 场景一：碎片化学习

> **用户画像：** 小李，上班族，每天通勤地铁上约 20 分钟
>
> **场景描述：** 小李每天早上坐地铁上班，打开"冷知识星球"，通过上下滑动浏览知识卡片。他喜欢看"科学原理"类目的卡片，在首页顶部切换到"科学"类目后，连续浏览了 5 张卡片，看到一张关于"为什么天空是蓝色的"的卡片觉得很有趣，点击收藏按钮保存。浏览满 3 张后，首页顶部弹出打卡成功的提示，小李感到很有成就感。

#### 场景二：AI 探索延伸

> **用户画像：** 小王，大学生，对自然科学充满好奇
>
> **场景描述：** 小王在浏览一张关于"章鱼有三颗心脏"的知识卡片时，想要了解更多相关知识。他点击卡片上的 AI 延伸解读按钮，底部弹出面板，展示 AI 生成的 3 条延伸知识："章鱼的血液为什么是蓝色的"、"章鱼的神经元分布"、"其他拥有多颗心脏的动物"。小王逐条阅读，觉得内容很有价值，将其中一条收藏起来。

#### 场景三：打卡坚持

> **用户画像：** 小张，自由职业者，希望培养每日学习习惯
>
> **场景描述：** 小张已经连续打卡 25 天了，他打开小程序查看个人中心，看到打卡日历上密密麻麻的打卡标记和"连续打卡 25 天"的数字，感到很有动力。今天他浏览了 3 张卡片后完成打卡，系统提示"距离 30 天里程碑还差 5 天，继续加油！"。

#### 场景四：纠错贡献

> **用户画像：** 小陈，中学物理老师，对知识准确性要求高
>
> **场景描述：** 小陈在浏览一张关于"光速"的知识卡片时，发现描述中的数据有误。他点击卡片上的纠错按钮，选择纠错类型为"内容错误"，在描述中详细说明了正确数据，并留下了联系方式。提交后，系统提示"纠错提交成功，感谢您的贡献！"。几天后，小陈收到消息通知，他的纠错已被采纳。

#### 场景五：图片识别探索

> **用户画像：** 小刘，旅行爱好者，喜欢探索新鲜事物
>
> **场景描述：** 小刘在公园散步时看到一种不认识的花，拍了一张照片。他打开"冷知识星球"，点击首页的相机图标按钮，选择刚才拍的照片上传。AI 识别后生成了 2 张相关知识卡片："这种花的名称和特征"、"该植物的分布与习性"。小刘觉得很有趣，将两张卡片都收藏了。

## 第四章：功能需求详细说明

### 4.1 用户系统

#### 4.1.1 微信授权登录

**功能描述：** 用户通过微信授权完成登录，获取用户唯一标识（OpenID）及基本信息。

**入口：**
- 首次打开小程序时自动弹出登录引导弹窗
- 访客触发需要登录的功能（收藏、纠错、打卡、AI 功能等）时弹出登录引导弹窗

**操作流程：**

```
用户打开小程序
    │
    ▼
检查本地是否有登录态（token）
    │
    ├── 有 ──► 验证 token 有效性
    │           │
    │           ├── 有效 ──► 进入首页
    │           └── 无效 ──► 清除本地 token，弹出登录引导
    │
    └── 无 ──► 弹出登录引导弹窗
                │
                ▼
        用户点击"微信登录"按钮
                │
                ▼
        调用 wx.login() 获取 code
                │
                ▼
        将 code 发送至后端接口
                │
                ▼
        后端通过 code 换取 OpenID + SessionKey
                │
                ▼
        后端生成 token，返回给前端
                │
                ▼
        前端存储 token 到本地
                │
                ▼
        弹出头像昵称授权弹窗（可选）
                │
                ├── 用户同意 ──► 获取头像昵称，更新用户信息
                │
                └── 用户拒绝 ──► 使用默认头像和昵称"知识探索者"
                │
                ▼
        进入首页
```

**业务规则：**
1. 登录采用静默授权（wx.login）+ 头像昵称授权两步走策略
2. 静默授权为必须步骤，头像昵称授权为可选步骤
3. 用户拒绝头像昵称授权后，使用系统默认头像（星球图标）和默认昵称"知识探索者"
4. Token 有效期为 7 天，过期后自动重新登录
5. 每次打开小程序时检查 token 有效性，无效则静默刷新

**界面要求：**
- 登录引导弹窗采用半透明遮罩 + 居中卡片样式
- 弹窗包含产品 Logo、产品名称、Slogan、微信登录按钮
- 微信登录按钮使用微信官方绿色（ ` #07C160` ），圆角矩形，宽度 80% 屏幕宽度

#### 4.1.2 用户信息管理

**功能描述：** 已登录用户可修改头像和昵称。

**入口：** 个人中心页 → 点击用户头像/昵称区域

**操作流程：**
1. 用户进入个人中心页，点击头像/昵称区域
2. 进入用户信息编辑页
3. 点击头像区域，调用微信头像选择能力（从相册选择或拍照）
4. 点击昵称输入框，弹出微信昵称输入组件
5. 点击"保存"按钮，提交修改请求
6. 修改成功后返回个人中心页，展示更新后的信息

**业务规则：**
1. 头像图片限制：支持 JPG、PNG 格式，大小不超过 2MB
2. 昵称长度限制：2-20 个字符
3. 昵称内容需符合微信昵称规范，不可包含特殊符号和违规内容
4. 头像和昵称可分别修改，也可同时修改
5. 修改后实时同步到个人中心页展示

**界面要求：**
- 编辑页顶部展示当前头像（圆形，120rpx），点击可更换
- 昵称输入框下方显示字符计数（如"5/20"）
- 保存按钮为主色调按钮，位于页面底部

### 4.2 首页-知识卡片流

#### 4.2.1 卡片内容结构

**功能描述：** 每张知识卡片是小程序的核心内容单元，以图文形式展示一条冷知识。

**卡片内容组成：**

| 组成部分 | 说明 | 规范要求 |
|---------|------|---------|
| 知识标题 | 简洁概括知识点的标题 | 最多 30 个字符，加粗显示 |
| 知识描述 | 详细描述知识内容 | 100-200 字，正文样式 |
| 配图 | 与知识相关的图片 | 建议尺寸 750×500px，支持 JPG/PNG |
| 类目标签 | 所属知识类目 | 显示在卡片左上角或右上角，小标签样式 |
| 来源标注 | 知识内容的参考来源 | 显示在卡片底部，灰色小字 |

**界面要求：**
- 卡片整体采用圆角矩形样式，圆角 16rpx
- 卡片背景色 ` #FFFFFF`，页面背景色 ` #F5F5F5`
- 卡片内边距：上下 32rpx，左右 32rpx
- 标题字体：32rpx，加粗，颜色 ` #333333`
- 描述字体：28rpx，常规，颜色 ` #666666`，行高 1.6
- 配图：宽度撑满卡片，高度自适应，最大高度 400rpx，圆角 12rpx
- 类目标签：背景色 ` #4A90D9`，文字颜色 ` #FFFFFF`，字号 22rpx，圆角 8rpx
- 来源标注：字号 22rpx，颜色 ` #999999`

#### 4.2.2 上下滑动切换

**功能描述：** 用户通过上下滑动手势切换知识卡片，交互方式类似抖音/Tinder。

**操作流程：**
1. 用户在首页看到当前知识卡片
2. **上滑（手指向上滑动）：** 当前卡片向上滑出屏幕，下一张卡片从底部滑入
3. **下滑（手指向下滑动）：** 当前卡片向下滑出屏幕，上一张卡片从顶部滑入
4. 滑动过程中卡片跟随手指移动，松手后根据滑动距离和速度判断切换或回弹

**业务规则：**
1. 滑动触发阈值：手指滑动距离超过屏幕高度的 20% 或滑动速度超过 0.5px/ms 时触发切换
2. 未达到阈值的滑动，卡片回弹到原位
3. 首次进入首页时，从服务端获取推荐卡片列表（预加载 5 张）
4. 当已浏览卡片接近预加载列表末尾时（剩余 2 张），自动请求下一批卡片
5. 上滑到列表末尾时，显示"已经到底啦，换个类目看看吧"的提示
6. 下滑到第一张卡片时，无法继续下滑

**界面要求：**
- 卡片切换动画时长：300ms
- 切换动画采用 ease-out 缓动曲线
- 卡片切换时有轻微的缩放效果（当前卡片 scale 1.0 → 0.95，新卡片 scale 1.05 → 1.0）
- 切换过程中卡片有轻微的透明度变化（当前卡片 opacity 1.0 → 0.8）

#### 4.2.3 卡片操作

**功能描述：** 每张知识卡片底部提供操作按钮，用户可进行收藏、纠错和 AI 延伸解读。

| AI 延伸解读 | AI 图标 | 卡片底部右侧 | 触发 AI 延伸解读功能 |

**业务规则：**
1. 访客点击任意操作按钮时，弹出登录引导弹窗
2. 收藏按钮状态实时反映当前卡片的收藏状态（已收藏显示实心星星，未收藏显示空心星星）

4. AI 延伸解读按钮点击后触发 AI 延伸解读功能（详见 4.7 节）

**界面要求：**

- 按钮点击时有缩放动画（scale 1.0 → 0.9 → 1.0，时长 200ms）

#### 4.2.4 类目筛选栏

**功能描述：** 首页顶部提供横向滚动的类目标签栏，用户可按类目筛选知识卡片。

**操作流程：**
1. 用户在首页顶部看到类目筛选栏，默认选中"全部"
2. 左右滑动类目筛选栏，浏览所有类目
3. 点击某个类目标签，该标签高亮选中，卡片流刷新为该类目下的推荐卡片
4. 点击"全部"标签，恢复显示所有类目的推荐卡片

**业务规则：**
1. 类目筛选栏固定在页面顶部（TabBar 上方）
2. 切换类目后，卡片流重新加载，从第一张开始展示
3. 切换类目时显示加载动画（骨架屏），加载完成后展示新卡片
4. 类目筛选栏支持横向滚动，当前选中项自动滚动到可视区域中央
5. 每个类目标签右侧显示该类目下的卡片数量（如"科学 (128)"）

**界面要求：**
- 筛选栏高度：80rpx

- 标签选中样式：字号 26rpx，颜色 ` #FFFFFF`，背景色 ` #4A90D9`，圆角 32rpx，内边距 12rpx 24rpx

#### 4.2.5 卡片推荐算法

**功能描述：** 后端根据推荐策略为用户返回知识卡片列表。

**推荐策略：**
1. **随机推荐（默认）：** 从所有知识卡片中随机选取，确保内容多样性
2. **类目筛选推荐：** 用户选择特定类目后，从该类目下的卡片中随机选取
3. **去重策略：** 同一用户在最近 7 天内不会重复推荐已浏览过的卡片
4. **新卡优先：** 新上架的知识卡片（7 天内发布）权重提升 20%
5. **质量权重：** 被收藏次数多的卡片推荐权重适当提升

**业务规则：**
1. 每次请求返回 5 张卡片
2. 推荐结果缓存在服务端，同一用户 10 分钟内重复请求返回缓存结果
3. 当某类目下卡片数量不足 5 张时，返回该类目下全部卡片

### 4.4 收藏功能

#### 4.4.1 收藏/取消收藏

**功能描述：** 用户可将感兴趣的知识卡片收藏到个人收藏夹，也可取消收藏。

**入口：**
- 首页知识卡片 → 收藏按钮
- 知识详情页 → 收藏按钮

**操作流程：**

**收藏流程：**
```
用户点击收藏按钮（空心星星）
    │
    ▼
检查登录状态
    │
    ├── 未登录 ──► 弹出登录引导弹窗
    │
    └── 已登录 ──► 发送收藏请求至后端
                    │
                    ▼
                后端创建收藏记录
                    │
                    ▼
                返回成功响应
                    │
                    ▼
                前端更新按钮状态（空心 → 实心）
                播放收藏成功动画（星星放大弹跳）
                显示 Toast 提示"收藏成功"
```

**取消收藏流程：**
```
用户点击收藏按钮（实心星星）
    │
    ▼
发送取消收藏请求至后端
    │
    ▼
后端删除收藏记录（逻辑删除）
    │
    ▼
返回成功响应
    │
    ▼
前端更新按钮状态（实心 → 空心）
显示 Toast 提示"已取消收藏"
```

**业务规则：**
1. 收藏操作为即时生效，无需二次确认
2. 取消收藏同样为即时生效，无需二次确认
3. 收藏/取消收藏操作有网络失败重试机制（最多重试 2 次）
4. 离线状态下点击收藏按钮，提示"网络异常，请稍后重试"
5. 收藏成功后，个人中心的收藏数量实时更新

**界面要求：**
- 收藏成功动画：星星图标从 scale 1.0 放大到 1.3 再回到 1.0，同时颜色从灰色变为红色，时长 300ms
- Toast 提示显示在屏幕中下方，1.5 秒后自动消失

#### 4.4.2 收藏列表

**功能描述：** 用户可在个人中心查看所有已收藏的知识卡片。

**入口：** 个人中心 → 我的收藏

**页面功能：**
1. **搜索：** 顶部搜索栏，支持按标题关键词搜索收藏的卡片
2. **类目筛选：** 搜索栏下方提供类目筛选标签，可按类目过滤收藏列表
3. **卡片列表：** 以列表形式展示收藏的知识卡片，每项包含缩略图、标题、描述摘要、类目、收藏时间
4. **点击查看：** 点击某条收藏记录，跳转至知识详情页

**业务规则：**
1. 收藏列表默认按收藏时间倒序排列（最新收藏的排在最前面）
2. 搜索为实时搜索（输入即搜索，防抖 300ms）
3. 类目筛选与搜索可叠加使用
4. 列表采用分页加载，每页 10 条，上拉加载更多
5. 取消收藏后，该卡片从收藏列表中移除（带淡出动画）

**界面要求：**
- 搜索栏高度 72rpx，背景色 ` #F5F5F5`，圆角 36rpx
- 列表项高度约 200rpx，包含左侧缩略图（160rpx × 120rpx）和右侧文字信息
- 列表项之间有 1rpx 分割线，颜色 ` #EEEEEE`
- 空状态展示插画 + "还没有收藏任何知识卡片哦"提示文字

4. 提示弹窗包含"我知道了"和"前往清理"两个按钮

### 4.5 纠错功能

#### 4.5.1 纠错入口

**功能描述：** 用户发现知识卡片内容有误时，可通过纠错功能提交修正意见。

**入口：**
- 首页知识卡片 → 纠错按钮
- 知识详情页 → 纠错按钮

**业务规则：**
1. 访客点击纠错按钮时，弹出登录引导弹窗
2. 已登录用户点击纠错按钮后，跳转至纠错提交页

#### 4.5.2 纠错提交

**功能描述：** 用户在纠错提交页填写纠错信息并提交。

**页面内容：**

| 区域 | 内容 | 类型 | 是否必填 |
|------|------|------|---------|
| 卡片信息 | 当前知识卡片的标题和缩略图 | 展示 | - |
| 纠错类型 | 内容错误 / 分类错误 / 图片不符 / 其他 | 单选 | 是 |
| 纠错描述 | 用户对错误的详细描述 | 多行文本 | 是 |
| 联系方式 | 用户可选填的联系方式（微信号/手机号） | 单行文本 | 否 |
| 提交按钮 | "提交纠错" | 按钮 | - |

**业务规则：**
1. 纠错描述字数限制：10-500 字
2. 联系方式格式校验：如填写手机号需为 11 位数字，微信号需为 6-20 位字母数字组合
3. 提交前校验必填项，未填写时对应字段下方显示红色提示文字
4. 提交成功后显示成功页面，包含"感谢您的纠错，我们会尽快审核"提示和"返回"按钮
5. 同一用户对同一张卡片最多提交 3 次纠错（详见 4.5.4）

**界面要求：**
- 纠错类型采用横向排列的单选按钮组，选中项有蓝色边框和背景
- 纠错描述输入框高度 200rpx，带字数计数（如"0/500"）
- 联系方式输入框下方有灰色提示文字"选填，方便我们与您沟通"
- 提交按钮为主色调按钮，宽度 100%

#### 4.5.3 纠错处理流程

**功能描述：** 用户提交的纠错由后台管理员审核处理。

**处理流程：**

```
用户提交纠错
    │
    ▼
纠错状态：待审核
    │
    ▼
后台管理员审核
    │
    ├── 采纳 ──► 纠错状态：已采纳
    │             │
    │             ├── 修改知识卡片内容
    │             │
    │             └── 发送消息通知用户"您的纠错已被采纳，感谢贡献！"
    │
    └── 驳回 ──► 纠错状态：已驳回
                  │
                  └── 发送消息通知用户"您的纠错未通过审核"
                      （可选附驳回原因）
```

**业务规则：**
1. 纠错提交后状态为"待审核"
2. 管理员需在 7 个工作日内完成审核
3. 审核结果通过微信小程序订阅消息通知用户
4. 用户可在"纠错记录"页查看所有提交的纠错及其状态
5. 被采纳的纠错次数可在个人中心展示，作为贡献值

#### 4.5.4 纠错限制

**功能描述：** 为防止恶意纠错和重复提交，对纠错次数进行限制。

**业务规则：**
1. 同一用户对同一张知识卡片最多提交 3 次纠错
2. 达到限制后，纠错按钮置灰不可点击，并显示提示"该卡片已提交 3 次纠错"
3. 每位用户每日最多提交 20 次纠错（防止批量提交）
4. 达到每日限制后，提示"今日纠错次数已用完，明天再来吧"

#### 4.7.1 功能描述

基于当前知识卡片的内容，AI 自动生成 2-3 条延伸相关知识或趣味解读，帮助用户更深入地探索感兴趣的知识领域。

### 4.9 每日打卡

#### 4.9.1 打卡规则

**功能描述：** 用户每日浏览一定数量的知识卡片后，可完成当日打卡。

**打卡条件：**
1. 每日浏览知识卡片数量 ≥ 3 张（浏览定义：卡片在屏幕上停留时间 ≥ 2 秒）
2. 每日仅可打卡 1 次
3. 打卡时间范围：当日 00:00 - 23:59:59

**业务规则：**
1. 系统实时统计当日已浏览卡片数量（有效浏览）
2. 当有效浏览数量达到 3 张时，首页顶部弹出打卡提醒横幅："今日已浏览 3 张卡片，快去打卡吧！"
3. 用户点击打卡按钮完成打卡，打卡成功后显示打卡成功动画
4. 打卡成功后，打卡提醒横幅变为"今日已打卡 ✓"，不再可点击
5. 不支持补签（详见 4.9.5）

#### 4.9.2 打卡入口

| 入口位置 | 说明 |
|---------|------|
| 首页顶部 | 打卡提醒横幅，满足条件时显示，点击完成打卡 |
| 个人中心 | 打卡入口卡片，显示今日打卡状态和连续打卡天数 |

**界面要求：**
- 首页打卡横幅：背景色 ` #FFF8E1`（浅黄色），高度 72rpx，圆角 0
- 横幅文字："今日已浏览 X 张卡片，快去打卡吧！"，字号 24rpx，颜色 ` #FF8F00`
- 打卡成功后横幅变为绿色背景 ` #E8F5E9`，文字"今日已打卡 ✓"，颜色 ` #4CAF50`
- 个人中心打卡卡片：背景色 ` #4A90D9`，白色文字，圆角 16rpx

   - 连续打卡天数（高亮显示）

   - 按月展示日历
   - 已打卡日期用圆点标记（颜色 ` #4A90D9`）

   - 支持左右滑动切换月份

**业务规则：**
