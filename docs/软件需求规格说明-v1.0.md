## 第一章：文档概述

### 1.1 文档目的

本文档为"冷知识星球"微信小程序的软件需求规格说明书（Product Requirements Document），旨在全面、清晰地描述产品的功能需求、非功能需求、数据结构及接口规范。

**目标读者：**

| 角色 | 阅读重点 |
|------|---------|
| 产品经理 | 全文，重点关注功能需求与业务规则 |
| UI/UX 设计师 | 第三、四章，重点关注页面结构与界面要求 |
| 前端开发 | 第三、四、七章，重点关注交互流程与接口规范 |
| 后端开发 | 第四、六、七章，重点关注业务规则、数据字典与接口设计 |
| 测试工程师 | 第四、五、七章，重点关注业务规则、性能要求与接口测试用例 |

### 1.2 产品概述

**冷知识星球**是一款面向碎片化学习场景的微信小程序，以图文卡片的形式向用户推送涵盖生活、大自然、科学、数学、历史等多个类目的小知识。用户可通过上下滑动浏览知识卡片，利用每天的零散时间轻松获取有趣的知识。产品同时集成 AI 能力，提供知识延伸解读和图片识别功能，帮助用户更深入地探索感兴趣的知识领域。

**产品定位：** 轻量级知识科普类微信小程序

**核心价值：**
- 碎片时间高效利用，每日进步一点点
- 丰富的知识类目，满足多元化兴趣
- AI 赋能，深度探索感兴趣的知识
- 每日打卡机制，培养持续学习习惯

### 1.3 品牌理念

> **探索未知，每日进步一点点**

冷知识星球相信，知识的积累源于每一天的好奇与探索。我们致力于将浩瀚的知识海洋浓缩为一张张精美的卡片，让用户在等车、排队、休息的碎片时间里，轻松获取一个有趣的知识点。每一次滑动都是一次小小的发现，每一天的坚持都是一次成长。

### 1.4 术语定义

| 术语 | 定义 |
|------|------|
| 知识卡片 | 小程序中最基本的内容单元，包含知识标题、文字描述、配图、类目标签等信息 |
| 类目 | 知识卡片的分类标签，如"生活常识"、"科学原理"等，共10个类目 |
| 收藏 | 用户将感兴趣的知识卡片保存到个人收藏夹的功能 |
| 纠错 | 用户对知识卡片内容提出修正意见的功能，包括内容错误、分类错误等 |
| 打卡 | 用户每日浏览一定数量的知识卡片后，记录当日学习行为的功能 |
| AI 延伸解读 | 基于当前知识卡片，由 AI 生成 2-3 条延伸相关知识或趣味解读的功能 |
| AI 图片识别 | 用户上传图片，由 AI 识别图片内容并生成相关知识卡片的功能 |
| 访客 | 未登录的用户，可浏览知识卡片但无法使用收藏、纠错、打卡等个性化功能 |
| 普通用户 | 已通过微信授权登录的用户，可使用全部功能 |
| 连续打卡 | 用户连续多日完成打卡的记录，中断后重新计数 |
| 里程碑 | 连续打卡达到特定天数（7天/30天/100天）时的成就标记 |

## 第二章：用户角色与场景

### 2.1 用户角色

#### 2.1.1 角色总览

**客户端用户：**

| 角色 | 描述 | 核心诉求 | 使用频率 |
|------|------|---------|---------|
| 访客 | 未进行微信授权登录的用户 | 快速浏览知识卡片，了解产品功能 | 偶尔（首次使用时） |
| 普通用户 | 已通过微信授权登录的用户 | 每日获取有趣知识、收藏喜欢的卡片、坚持打卡 | 每日 1-5 次 |

**后台管理用户：**

| 角色 | 描述 | 核心诉求 | 使用频率 |
|------|------|---------|---------|
| 超级管理员 | 系统最高权限管理者 | 系统配置、管理员管理、全局数据监控 | 每日 |
| 内容管理员 | 负责知识卡片内容管理 | 卡片增删改查、批量导入、类目管理 | 每日 |
| 运营人员 | 负责用户运营和数据统计 | 用户管理、数据统计、纠错管理 | 每日 |
| 审核人员 | 负责内容审核 | 纠错审核、内容质量把控 | 每日 |

#### 2.1.2 访客

- **描述：** 首次打开小程序或未进行微信授权的用户，处于"浏览模式"。
- **核心诉求：** 快速体验产品，了解知识卡片的内容质量和交互方式。
- **权限范围：**
  - 可浏览知识卡片（上下滑动切换）
  - 可按类目筛选卡片
  - 不可收藏、纠错、打卡、使用 AI 功能
  - 触发需要登录的功能时，弹出登录引导弹窗

#### 2.1.3 普通用户

- **描述：** 已完成微信授权登录的用户，拥有产品的完整使用权限。
- **核心诉求：**
  - 每日获取有趣的小知识，充实碎片时间
  - 收藏有价值的知识卡片，方便回顾
  - 通过打卡机制坚持每日学习
  - 利用 AI 功能深度探索感兴趣的知识
- **权限范围：** 可使用全部功能，包括收藏、纠错、打卡、AI 延伸解读、AI 图片识别等。

#### 2.1.4 超级管理员

- **描述：** 系统最高权限管理者，负责系统整体运营和管理。
- **核心诉求：**
  - 管理所有管理员账号和权限
  - 监控系统运行状态和数据统计
  - 配置系统参数和推荐算法
  - 处理紧急问题和异常情况
- **权限范围：**
  - 所有后台管理功能
  - 管理员账号管理
  - 系统配置管理
  - 数据导出和备份

#### 2.1.5 内容管理员

- **描述：** 负责知识卡片内容的创建、编辑和管理。
- **核心诉求：**
  - 高效管理知识卡片内容
  - 批量导入知识卡片
  - 维护类目体系
  - 保证内容质量和准确性
- **权限范围：**
  - 知识卡片增删改查
  - 批量导入功能
  - 类目管理
  - 内容统计查看

#### 2.1.6 运营人员

- **描述：** 负责用户运营、数据分析和纠错管理。
- **核心诉求：**
  - 了解用户行为和偏好
  - 处理用户反馈和纠错
  - 分析运营数据
  - 优化用户体验
- **权限范围：**
  - 用户管理（查看、禁用）
  - 数据统计和分析
  - 纠错管理（查看、分配）
  - 运营报告生成

#### 2.1.7 审核人员

- **描述：** 负责内容审核和纠错处理，保证内容质量。
- **核心诉求：**
  - 审核用户提交的纠错
  - 保证知识卡片内容准确性
  - 维护内容质量标准
- **权限范围：**
  - 纠错审核（采纳/驳回）
  - 内容审核
  - 审核记录查看

### 2.2 用户场景

#### 场景一：碎片化学习

> **用户画像：** 小李，上班族，每天通勤地铁上约 20 分钟
>
> **场景描述：** 小李每天早上坐地铁上班，打开"冷知识星球"，通过上下滑动浏览知识卡片。他喜欢看"科学原理"类目的卡片，在首页顶部切换到"科学"类目后，连续浏览了 5 张卡片，看到一张关于"为什么天空是蓝色的"的卡片觉得很有趣，点击收藏按钮保存。浏览满 3 张后，首页顶部弹出打卡成功的提示，小李感到很有成就感。

#### 场景二：AI 探索延伸

> **用户画像：** 小王，大学生，对自然科学充满好奇
>
> **场景描述：** 小王在浏览一张关于"章鱼有三颗心脏"的知识卡片时，想要了解更多相关知识。他点击卡片上的 AI 延伸解读按钮，底部弹出面板，展示 AI 生成的 3 条延伸知识："章鱼的血液为什么是蓝色的"、"章鱼的神经元分布"、"其他拥有多颗心脏的动物"。小王逐条阅读，觉得内容很有价值，将其中一条收藏起来。

#### 场景三：打卡坚持

> **用户画像：** 小张，自由职业者，希望培养每日学习习惯
>
> **场景描述：** 小张已经连续打卡 25 天了，他打开小程序查看个人中心，看到打卡日历上密密麻麻的打卡标记和"连续打卡 25 天"的数字，感到很有动力。今天他浏览了 3 张卡片后完成打卡，系统提示"距离 30 天里程碑还差 5 天，继续加油！"。

#### 场景四：纠错贡献

> **用户画像：** 小陈，中学物理老师，对知识准确性要求高
>
> **场景描述：** 小陈在浏览一张关于"光速"的知识卡片时，发现描述中的数据有误。他点击卡片上的纠错按钮，选择纠错类型为"内容错误"，在描述中详细说明了正确数据，并留下了联系方式。提交后，系统提示"纠错提交成功，感谢您的贡献！"。几天后，小陈收到消息通知，他的纠错已被采纳。

#### 场景五：图片识别探索

> **用户画像：** 小刘，旅行爱好者，喜欢探索新鲜事物
>
> **场景描述：** 小刘在公园散步时看到一种不认识的花，拍了一张照片。他打开"冷知识星球"，点击首页的相机图标按钮，选择刚才拍的照片上传。AI 识别后生成了 2 张相关知识卡片："这种花的名称和特征"、"该植物的分布与习性"。小刘觉得很有趣，将两张卡片都收藏了。

#### 场景六：内容批量导入

> **用户画像：** 张经理，内容管理员，负责知识卡片内容管理
>
> **场景描述：** 张经理收到运营团队整理的 100 条知识卡片数据，包含 Excel 文件和配图压缩包。他登录后台管理系统，进入知识卡片管理页面，点击"批量导入"按钮。系统引导他上传 Excel 文件和图片压缩包，预览前 10 条数据确认无误后，点击"开始导入"。系统自动处理并上传图片到 CDN，5 分钟后导入完成，显示成功 98 条、失败 2 条（格式错误），张经理下载错误报告进行修正。

#### 场景七：纠错审核处理

> **用户画像：** 李审核，审核人员，负责处理用户纠错
>
> **场景描述：** 李审核登录后台管理系统，看到有 15 条待审核的纠错。他逐条查看，发现有一条关于"光速"知识卡片的纠错，用户指出描述中的数据有误。李审核核实后确认纠错正确，点击"采纳"按钮，选择"自动更新"选项。系统自动更新知识卡片内容，并记录审核日志。用户收到消息通知，纠错已被采纳。

#### 场景八：系统配置管理

> **用户画像：** 王总，超级管理员，负责系统整体运营
>
> **场景描述：** 王总登录后台管理系统，查看系统数据统计：今日活跃用户 5000+，新增用户 200+，知识卡片浏览量 50000+。他发现推荐算法效果不佳，进入系统配置页面，调整推荐权重：将内容相似度权重从 40% 调整为 35%，热度权重从 30% 调整为 35%。配置保存后，系统自动应用新的推荐策略。

#### 3.4.3 数据库选型说明

**PostgreSQL（主数据库）**

| 特性 | 应用场景 |
|------|---------|
| UUID 主键 | 所有表使用 UUID 作为主键，避免自增 ID 的安全风险和分布式冲突 |
| JSONB | 存储灵活的配置数据、AI 返回结果等半结构化数据 |
| 全文搜索 | 知识卡片标题和描述的基础搜索（复杂搜索使用 Elasticsearch） |
| 外键约束 | 保证数据完整性，支持级联删除 |
| 索引优化 | 支持 B-tree、Hash、GiST、GIN 等多种索引类型 |
| 事务支持 | 保证数据一致性，支持复杂业务逻辑 |

**Redis（缓存/队列）**

| 特性 | 应用场景 |
|------|---------|
| 会话管理 | 存储管理员 Token、用户会话信息 |
| 热点缓存 | 缓存热门知识卡片、类目列表、系统配置 |
| 限流计数 | API 接口限流、AI 功能使用次数限制 |
| 任务队列 | Bull 队列，处理批量导入、异步任务 |
| 排行榜 | 打卡排行榜、热门卡片排行 |
| 发布订阅 | 实时通知、消息推送 |

**MongoDB（日志存储）**

| 特性 | 应用场景 |
|------|---------|
| 灵活 Schema | 操作日志、推荐日志等结构不固定的数据 |
| 高写入性能 | 日志数据写入频繁，MongoDB 写入性能优异 |
| TTL 索引 | 自动过期删除旧日志数据 |
| 聚合管道 | 复杂的日志统计和分析 |
| 分片支持 | 数据量大时可水平扩展 |

**Elasticsearch（搜索引擎）**

| 特性 | 应用场景 |
|------|---------|
| 全文搜索 | 知识卡片标题、描述的模糊搜索 |
| 分词器 | 中文分词，支持拼音搜索 |
| 聚合统计 | 按类目、标签聚合统计 |
| 相关性评分 | 搜索结果按相关性排序 |
| 近实时 | 数据更新后近实时可搜索 |

#### 4.1.2 微信小程序登录流程

**功能描述：** 用户通过微信授权完成登录，获取用户唯一标识（OpenID）及基本信息。

**入口：**
- 首次打开小程序时自动弹出登录引导弹窗
- 访客触发需要登录的功能（收藏、纠错、打卡、AI 功能等）时弹出登录引导弹窗

**操作流程：**

```
用户打开小程序
    │
    ▼
检查本地是否有登录态（token）
    │
    ├── 有 ──► 验证 token 有效性
    │           │
    │           ├── 有效 ──► 进入首页
    │           └── 无效 ──► 清除本地 token，弹出登录引导
    │
    └── 无 ──► 弹出登录引导弹窗
                │
                ▼
        用户点击"微信登录"按钮
                │
                ▼
        调用 wx.login() 获取 code
                │
                ▼
        将 code 发送至后端接口
                │
                ▼
        后端通过 code 换取 OpenID + SessionKey
                │
                ▼
        后端生成 token，返回给前端
                │
                ▼
        前端存储 token 到本地
                │
                ▼
        弹出头像昵称授权弹窗（可选）
                │
                ├── 用户同意 ──► 获取头像昵称，更新用户信息
                │
                └── 用户拒绝 ──► 使用默认头像和昵称"知识探索者"
                │
                ▼
        进入首页
```

**业务规则：**
1. 登录采用静默授权（wx.login）+ 头像昵称授权两步走策略
2. 静默授权为必须步骤，头像昵称授权为可选步骤
3. 用户拒绝头像昵称授权后，使用系统默认头像（星球图标）和默认昵称"知识探索者"
4. Token 有效期为 7 天，过期后自动重新登录
5. 每次打开小程序时检查 token 有效性，无效则静默刷新

#### 4.1.5 登录绑定与解绑

**功能描述：** 用户可以绑定多个登录方式，方便在不同平台登录同一账号。

**入口：** 个人中心 → 设置 → 账号安全 → 登录方式管理

**绑定状态展示：**

```
│  Apple ID   [已绑定]          [解绑]   │  ← iOS
│                                         │
```

**绑定流程（以绑定手机号为例）：**

```
用户点击手机号"绑定"按钮
        │
        ▼
输入手机号码
        │
        ▼
获取并输入验证码
        │
        ▼

        │
        ├── 手机号已被其他账号绑定
        │       │
        │       ▼

        │       │
        │       ├── 确认 ──► 解除原账号绑定，绑定到当前账号
        │       └── 取消 ──► 返回
        │
        └── 手机号未绑定 ──► 绑定成功
                │
                ▼
        提示"绑定成功"
```

**解绑流程：**

```
用户点击"解绑"按钮
        │
        ▼
检查当前账号登录方式数量
        │
        ├── 仅剩 1 种登录方式
        │       │
        │       ▼

        │

                ▼

                │

                └── 取消 ──► 返回
```

**业务规则：**
1. 用户至少保留一种有效的登录方式
2. 同一第三方账号（微信/QQ/抖音）只能绑定一个用户账号
3. 同一手机号只能绑定一个用户账号
4. 同一邮箱只能绑定一个用户账号
5. 解绑时需验证用户身份（输入验证码或密码）
6. 绑定已存在的第三方账号时，提示用户是否合并账号
7. 账号合并后，原账号的收藏、打卡记录等数据合并到新账号

#### 4.1.6 用户信息管理

**功能描述：** 已登录用户可修改头像和昵称。

**入口：** 个人中心页 → 点击用户头像/昵称区域

**操作流程：**
1. 用户进入个人中心页，点击头像/昵称区域
2. 进入用户信息编辑页
3. 点击头像区域，调用头像选择能力（从相册选择或拍照）
4. 点击昵称输入框，输入新昵称
5. 点击"保存"按钮，提交修改请求
6. 修改成功后返回个人中心页，展示更新后的信息

**业务规则：**
1. 头像图片限制：支持 JPG、PNG 格式，大小不超过 2MB
2. 昵称长度限制：2-20 个字符
3. 昵称内容需符合规范，不可包含特殊符号和违规内容
4. 头像和昵称可分别修改，也可同时修改

#### 4.2.5 卡片推荐算法

**功能描述：** 为用户提供个性化的知识卡片推荐，提升用户粘性和内容消费效率。

**推荐策略：**

| 策略 | 权重 | 说明 |
|------|------|------|
| 基于用户兴趣推荐 | 40% | 根据用户历史行为推荐相似内容 |
| 热度推荐 | 30% | 推荐热门、高收藏的知识卡片 |
| 新卡片优先 | 20% | 优先推荐新上架的知识卡片 |
| 随机推荐 | 10% | 保证内容多样性 |

**算法流程：**

```
用户请求推荐卡片
    ↓
检查用户登录状态
    ├── 已登录 → 个性化推荐
    │   ├── 获取用户兴趣标签（基于历史浏览、收藏、纠错）
    │   ├── 获取用户已浏览卡片ID列表
    │   ├── 调用推荐算法
    │   │   ├── 1. 基于内容相似度推荐（40%）
    │   │   ├── 2. 基于热度推荐（30%）
    │   │   ├── 3. 新卡片优先（20%）
    │   │   └── 4. 随机推荐（10%）
    │   └── 过滤已浏览卡片，返回结果
    │
    └── 未登录 → 热门推荐
        ├── 获取热门卡片列表
        └── 随机打乱顺序，返回结果
```

**用户兴趣标签计算：**

| 行为类型 | 权重 | 说明 |
|---------|------|------|
| 浏览历史 | 1.0 | 用户浏览过的卡片类目 |
| 收藏行为 | 3.0 | 用户收藏的卡片类目 |
| 纠错行为 | 2.0 | 用户提交纠错的卡片类目 |
| AI延伸解读 | 2.5 | 用户使用AI延伸解读的卡片类目 |

**兴趣分数计算公式：**
```
interest_score = Σ(行为权重 × 时间衰减因子)
```

**热度计算公式：**
```
热度分数 = 浏览数 × 1 + 收藏数 × 5 + 纠错数 × 2 + 时间衰减因子
```

**时间衰减因子：**

| 时间范围 | 衰减因子 |
|---------|---------|
| 7天内 | 1.0 |
| 7-30天 | 0.8 |
| 30-90天 | 0.5 |
| 90天以上 | 0.3 |

**新卡片优先策略：**
- 新卡片定义：上架时间在7天内
- 优先级：新卡片在推荐结果中占比20%
- 权重：新卡片基础权重 × 1.5

**去重策略：**
- 已浏览卡片：7天内不再推荐
- 已收藏卡片：30天内不再推荐（除非用户主动刷新）
- 用户主动刷新：忽略去重规则

**业务规则：**
1. 每次请求返回 5-10 张卡片
2. 推荐结果缓存在服务端，同一用户 10 分钟内重复请求返回缓存结果
3. 当某类目下卡片数量不足 5 张时，返回该类目下全部卡片
4. 推荐算法配置可在后台管理系统中动态调整

**推荐接口设计：**

请求参数：
```json
{
  "page": 1,
  "page_size": 10,
  "category_id": null,
  "refresh": false
}
```

返回参数：
```json
{
  "code": 200,
  "data": {
    "list": [
      {
        "id": 1,
        "title": "为什么天空是蓝色的",
        "description": "...",
        "image_url": "...",
        "category_id": 3,
        "category_name": "科学原理",
        "score": 85.5,
        "reason": "基于您的兴趣推荐"
      }
    ],
    "has_more": true,
    "recommend_strategy": "personalized"
  }
}
```

**推荐算法优化方向：**

短期优化：
- A/B测试不同权重组合
- 收集用户反馈（点赞/不感兴趣）
- 优化时间衰减因子

长期优化：
- 引入协同过滤算法
- 使用机器学习模型
- 实现实时推荐

| 纠错类型 | 内容错误 / 分类错误 / 图片不符 / 其他 | 单选 | 是 |
| 纠错描述 | 用户对错误的详细描述 | 多行文本 | 是 |
| 联系方式 | 用户可选填的联系方式（微信号/手机号） | 单行文本 | 否 |
| 提交按钮 | "提交纠错" | 按钮 | - |

**业务规则：**
1. 纠错描述字数限制：10-500 字
2. 联系方式格式校验：如填写手机号需为 11 位数字，微信号需为 6-20 位字母数字组合
3. 提交前校验必填项，未填写时对应字段下方显示红色提示文字
4. 提交成功后显示成功页面，包含"感谢您的纠错，我们会尽快审核"提示和"返回"按钮
5. 同一用户对同一张卡片最多提交 3 次纠错（详见 4.5.4）

**界面要求：**
- 纠错类型采用横向排列的单选按钮组，选中项有蓝色边框和背景
- 纠错描述输入框高度 200rpx，带字数计数（如"0/500"）
- 联系方式输入框下方有灰色提示文字"选填，方便我们与您沟通"
- 提交按钮为主色调按钮，宽度 100%

#### 4.5.3 纠错处理流程

**功能描述：** 用户提交的纠错由后台管理员审核处理。

**处理流程：**

```
用户提交纠错
    │
    ▼
纠错状态：待审核
    │
    ▼
后台管理员审核
    │
    ├── 采纳 ──► 纠错状态：已采纳
    │             │
    │             ├── 修改知识卡片内容
    │             │
    │             └── 发送消息通知用户"您的纠错已被采纳，感谢贡献！"
    │
    └── 驳回 ──► 纠错状态：已驳回
                  │
                  └── 发送消息通知用户"您的纠错未通过审核"
                      （可选附驳回原因）
```

**业务规则：**
1. 纠错提交后状态为"待审核"
2. 管理员需在 7 个工作日内完成审核
3. 审核结果通过微信小程序订阅消息通知用户
4. 用户可在"纠错记录"页查看所有提交的纠错及其状态
5. 被采纳的纠错次数可在个人中心展示，作为贡献值

#### 4.5.4 纠错限制

**功能描述：** 为防止恶意纠错和重复提交，对纠错次数进行限制。

**业务规则：**
1. 同一用户对同一张知识卡片最多提交 3 次纠错
2. 达到限制后，纠错按钮置灰不可点击，并显示提示"该卡片已提交 3 次纠错"
3. 每位用户每日最多提交 20 次纠错（防止批量提交）
4. 达到每日限制后，提示"今日纠错次数已用完，明天再来吧"

### 4.7 AI 知识延伸解读

#### 4.7.1 功能描述

基于当前知识卡片的内容，AI 自动生成 2-3 条延伸相关知识或趣味解读，帮助用户更深入地探索感兴趣的知识领域。

**核心能力：**
- 根据知识卡片内容，生成相关的延伸知识
- 每条延伸知识包含标题、描述和来源标注
- 延伸知识内容准确、有趣、与原卡片主题相关

#### 4.7.2 触发方式

**入口：**
- 首页知识卡片 → AI 延伸解读按钮
- 知识详情页 → AI 延伸解读按钮

**操作流程：**
1. 用户点击 AI 延伸解读按钮
2. 检查登录状态（未登录则弹出登录引导）
3. 检查当日剩余免费次数
4. 有剩余次数 → 调用 AI 接口，展示 Loading 动画
5. 无剩余次数 → 弹出提示（详见 4.7.4 使用限制）

#### 4.7.3 展示形式

**功能描述：** AI 延伸解读结果以底部弹出面板（Bottom Sheet）的形式展示。

**面板内容：**
1. **面板头部：** 标题"AI 延伸解读"，右侧关闭按钮
2. **原卡片摘要：** 简要展示当前知识卡片的标题（帮助用户回顾上下文）
3. **延伸知识列表：** 2-3 条延伸知识，每条包含：
   - 标题（加粗，可点击展开/收起）
   - 描述（展开后显示完整内容）
   - 来源标注（灰色小字）
4. **面板底部：** "换一批"按钮（消耗 1 次免费次数）

**界面要求：**
- 面板高度：屏幕高度的 70%
- 面板背景色 ` #FFFFFF`
- 面板从底部滑入，带圆角顶部（圆角 24rpx）
- 半透明遮罩层，点击遮罩关闭面板
- 延伸知识标题字号 30rpx，颜色 ` #333333`
- 延伸知识描述字号 28rpx，颜色 ` #666666`，行高 1.6
- 来源标注字号 22rpx，颜色 ` #999999`
- "换一批"按钮：主色调按钮，圆角 12rpx

#### 4.7.4 使用限制

**功能描述：** AI 延伸解读功能有每日使用次数限制。

**业务规则：**
1. 每位用户每日可免费使用 AI 延伸解读 10 次
2. 免费次数在每日 00:00 重置
3. 使用次数在 AI 按钮（或面板头部）旁显示，如"AI 延伸 (剩余 7 次)"

#### 4.9.3 激励视频广告流程

**功能描述：** 用户观看激励视频广告后，获得 AI 功能额外使用次数。

**触发场景：**
- AI 延伸解读免费次数用完时
- AI 图片识别免费次数用完时

**流程：**

```
用户点击"观看广告获取次数"
        │
        ▼
检查广告加载状态
        │
        ├── 广告已加载 ──► 展示激励视频广告
        │                       │
        │                       ▼
        │               用户观看广告（≥15秒）
        │                       │
        │                       ├── 完整观看 ──► 广告完成回调
        │                       │                       │
        │                       │                       ▼
        │                       │               后端记录广告奖励
        │                       │                       │
        │                       │                       ▼
        │                       │               增加 3 次使用机会
        │                       │                       │
        │                       │                       ▼
        │                       │               提示"获得 3 次机会"
        │                       │
        │                       └── 中途关闭 ──► 不奖励，提示"需完整观看"
        │
        └── 广告加载失败 ──► 提示"广告加载失败，请稍后重试"
```

**业务规则：**
1. 每日通过广告获取的额外次数上限：AI 延伸 3 次（9 次机会），AI 识别 3 次（9 次机会）
2. 广告必须完整观看（≥15 秒）才能获得奖励
3. 广告完成后，后端记录广告观看记录，防止重复奖励
4. 广告加载失败时，提供重试按钮
5. 网络异常时，提示用户检查网络

#### 4.9.4 插屏广告策略

3. 用户可点击关闭按钮跳过广告（展示 5 秒后显示关闭按钮）

### 4.10 每日打卡

#### 4.9.1 打卡规则

**功能描述：** 用户每日浏览一定数量的知识卡片后，可完成当日打卡。

**打卡条件：**
1. 每日浏览知识卡片数量 ≥ 3 张（浏览定义：卡片在屏幕上停留时间 ≥ 2 秒）
2. 每日仅可打卡 1 次
3. 打卡时间范围：当日 00:00 - 23:59:59

**业务规则：**
1. 系统实时统计当日已浏览卡片数量（有效浏览）
2. 当有效浏览数量达到 3 张时，首页顶部弹出打卡提醒横幅："今日已浏览 3 张卡片，快去打卡吧！"
3. 用户点击打卡按钮完成打卡，打卡成功后显示打卡成功动画
4. 打卡成功后，打卡提醒横幅变为"今日已打卡 ✓"，不再可点击
5. 不支持补签（详见 4.9.5）

#### 4.9.2 打卡入口

| 入口位置 | 说明 |
|---------|------|
| 首页顶部 | 打卡提醒横幅，满足条件时显示，点击完成打卡 |
| 个人中心 | 打卡入口卡片，显示今日打卡状态和连续打卡天数 |

**界面要求：**
- 首页打卡横幅：背景色 ` #FFF8E1`（浅黄色），高度 72rpx，圆角 0
- 横幅文字："今日已浏览 X 张卡片，快去打卡吧！"，字号 24rpx，颜色 ` #FF8F00`
- 打卡成功后横幅变为绿色背景 ` #E8F5E9`，文字"今日已打卡 ✓"，颜色 ` #4CAF50`
- 个人中心打卡卡片：背景色 ` #4A90D9`，白色文字，圆角 16rpx

#### 4.9.3 打卡记录

**功能描述：** 用户可在打卡日历页查看历史打卡记录。

**入口：** 个人中心 → 打卡日历

**页面内容：**
1. **顶部统计区：**
   - 累计打卡天数
   - 连续打卡天数（高亮显示）
   - 本月打卡天数
2. **日历视图：**
   - 按月展示日历
   - 已打卡日期用圆点标记（颜色 ` #4A90D9`）
   - 今日高亮显示
   - 支持左右滑动切换月份
3. **里程碑展示：** 已达成的里程碑以徽章形式展示

**业务规则：**
1. 日历默认展示当前月份
2. 支持查看最近 12 个月的打卡记录
3. 打卡数据从服务端获取，不依赖本地存储
4. 连续打卡天数计算：从今天往前连续打卡的天数（中间断开则重新计数）

**界面要求：**
- 日历网格 7 列（周一至周日），每格高度 80rpx
- 已打卡日期：日期数字下方显示 8rpx 的蓝色圆点
- 今日：日期数字外圈显示蓝色圆环
- 里程碑徽章：48rpx × 48rpx，金色（ ` #FFD700`）

#### 4.9.4 打卡激励

**功能描述：** 当用户连续打卡达到特定天数时，展示里程碑成就。

**里程碑设置：**

| 里程碑 | 连续打卡天数 | 奖励/提示 |
|--------|------------|----------|
| 初级探索者 | 7 天 | 弹出恭喜弹窗 + "初级探索者"徽章 |
| 知识达人 | 30 天 | 弹出恭喜弹窗 + "知识达人"徽章 |
| 知识大师 | 100 天 | 弹出恭喜弹窗 + "知识大师"徽章 |

**业务规则：**
1. 达到里程碑时，打卡成功后弹出恭喜弹窗（而非普通打卡成功提示）
2. 恭喜弹窗包含：成就名称、徽章图片、鼓励文案、"分享成就"按钮（暂不实现分享功能，按钮置灰）
3. 里程碑徽章展示在个人中心和打卡日历页
4. 每个里程碑只能达成一次，重复达到不重复弹窗
5. 连续打卡中断后，已获得的徽章保留，但连续天数重新计算

**界面要求：**
- 恭喜弹窗采用全屏遮罩 + 居中卡片样式
- 弹窗包含撒花/烟花动画效果
- 徽章图片居中展示，尺寸 200rpx × 200rpx
- 鼓励文案字号 32rpx，颜色 ` #333333`

#### 4.9.5 打卡补签

**业务规则：**
1. **不支持补签功能**
2. 用户漏打卡后，连续打卡天数归零重新计算
3. 在打卡日历中，未打卡日期正常显示，不做特殊标记
4. 个人中心连续打卡天数旁显示文案"坚持每日打卡，不要中断哦"

**业务规则：**

4. 审核记录永久保存
