# Git 提交前检查规则

## 触发条件

当用户执行 `git commit` 命令时，自动触发以下检查。

## 检查流程

### 1. 开发任务检查

检查 `docs/TASK.md` 文件：

1. **任务状态更新**
   - 如果提交涉及功能开发，检查对应任务是否已标记为完成 `[x]`
   - 如果任务状态未更新，提示用户更新任务状态

2. **任务关联验证**
   - 检查提交信息是否关联了任务编号
   - 示例：`feat(card): 实现卡片滑动 #TASK-2.2.1`

### 2. 开发日志检查

检查 `docs/DEVLOG.md` 文件：

1. **日志更新检查**
   - 如果是功能提交（`feat`），检查是否已添加开发日志
   - 如果是修复提交（`fix`），检查是否已记录问题和解决方案

2. **版本号检查**
   - 检查提交是否涉及版本号变更
   - 如果是版本发布，确保日志中已更新版本历史

### 3. 文档一致性检查

1. **任务与日志对应**
   - 检查已完成的任务是否在开发日志中有记录
   - 检查开发日志中的任务是否在任务清单中

2. **版本号一致性**
   - 检查 `package.json` 版本号与 DEVLOG 版本记录是否一致

## 检查输出

### 通过检查

```
✅ Git 提交前检查通过
- 开发任务状态: 已更新
- 开发日志: 已记录
- 文档一致性: 通过
```

### 未通过检查

```
⚠️ Git 提交前检查未通过

请完成以下操作：

1. 更新开发任务状态
   - 文件: docs/TASK.md
   - 任务: [任务编号] [任务描述]
   - 操作: 将 `[ ]` 更新为 `[x]`

2. 更新开发日志
   - 文件: docs/DEVLOG.md
   - 操作: 添加本次提交的开发记录

3. 确认版本号
   - 当前版本: [版本号]
   - 是否需要更新: [是/否]

完成上述操作后，请重新执行 git commit。
```

## 自动更新建议

### 任务状态更新模板

在 `docs/TASK.md` 中找到对应任务，更新状态：

```markdown
- [x] 2.2.1 实现上下滑动手势识别
```

### 开发日志更新模板

在 `docs/DEVLOG.md` 中添加记录：

```markdown
### YYYY-MM-DD - vX.X.X

**功能名称**

#### 完成任务

- [x] 任务描述

#### 技术实现

- 实现细节说明

#### 相关文件

- 文件路径列表
```

## 特殊情况处理

### 1. 紧急修复

对于紧急修复（`hotfix`），可以跳过任务检查，但必须：
- 在提交信息中注明 `[HOTFIX]`
- 在 24 小时内补充任务和日志更新

### 2. 文档提交

对于纯文档提交（`docs`），可以跳过任务检查，但必须：
- 确保文档格式正确
- 确保文档内容与代码一致

### 3. 重构提交

对于重构提交（`refactor`），需要：
- 更新相关任务状态
- 记录重构原因和影响范围

## 配置选项

在项目根目录创建 `.commit-check.config.json` 可自定义检查规则：

```json
{
  "enabled": true,
  "strictMode": false,
  "skipTypes": ["chore", "style", "test"],
  "requireTaskId": true,
  "autoUpdateLog": false
}
```

**配置说明**:

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| enabled | boolean | true | 是否启用检查 |
| strictMode | boolean | false | 严格模式（所有提交必须关联任务） |
| skipTypes | array | [] | 跳过检查的提交类型 |
| requireTaskId | boolean | true | 是否要求提交信息包含任务 ID |
| autoUpdateLog | boolean | false | 是否自动更新开发日志 |

---

*此规则由 Claude Code 自动执行，确保开发任务和日志的及时更新。*
